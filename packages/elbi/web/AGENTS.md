# Web app: working rules

The verifying-analysis chat SPA (React 19 + Vite + TypeScript, Tailwind v4, shadcn/ui
over Radix). Read `.interface-design/system.md` before touching styling.

## Commands

- `npm run dev`: dev server (proxies `/api` to the backend on :7700).
- `npm run lint` / `npm run lint:fix`: Biome check, then the ESLint design-system rules. Must be clean.
- `npm test`: Vitest (jsdom + Testing Library).
- `npm run build`: typecheck + production build into the Python package.

## Reuse before you build

Search for an existing piece before adding one. In particular:

| Need | Use | Not |
|---|---|---|
| the oracle's verdict | `<VerdictBadge>` | a raw badge / colored span |
| a status pill | `<Badge variant="...">` | an ad-hoc styled span |
| a data grid | `components/ui/data-table` | a raw `<table>` |
| a menu / dropdown | `components/ui/dropdown-menu`, `command` | a hand-rolled popover |
| a chart | `components/viz/VegaChart` (+ `lib/chart-theme`) | inline chart colors |
| primitives (button, card, dialog, select, …) | `components/ui/*` | new one-offs |
| a labelled form control | components/app/FormField | a label + span + fieldClass |
| an icon-only button | components/app/IconButton | a raw <button> with an svg |
| an empty list/page | components/app/EmptyState | a hand-rolled "No … yet" block |
| tabs | components/ui/tabs | a hand-rolled tab strip |

## Styling

- Use the **semantic** design tokens as Tailwind utilities (`bg-card`, `text-text-secondary`,
  `border-border`, `text-text-tertiary`, …). Never hardcode a hex/`oklch` color or a raw
  `--n-*` in a component. Charts are the one exception and go through `lib/chart-theme`.
- Depth is **borders-first**; use a shadow token only for a genuinely floating surface.
- Never branch on theme in a component: read semantic tokens and dark mode is automatic.

## Controls

- **Select**: label it with `FormField` and wrap the `SelectTrigger` in `FormControl`. Keep it
  controlled with the string state, `value={v}`; `""` is the placeholder state (never pass
  `undefined`, which drops Radix into uncontrolled mode and keeps the last pick on screen).
  Only a `SelectItem` may not have `value=""`: when empty is a real choice ("Auto",
  "Default"), give that item a named sentinel, map it to/from `""` at the `value` /
  `onValueChange` boundary only, and test that the API receives `""`.
- Icons inside `xs` / `icon-xs` buttons take `size-*` (e.g. `size-4`), not `h-4 w-4`, or the
  button shrinks them to 12px.
- Adjacent icon buttons must not have overlapping hit boxes: a negative-margin footprint
  goes on one axis only (`-my-*`) when buttons sit side by side.
- Segmented controls mark the chosen option `aria-pressed`; navigation lists mark the
  active item `aria-current="page"`. `TabsTrigger` needs a matching `TabsContent`.
- Migrating markup onto a component: accept the component's own defaults (sizes, chrome,
  hover); fix anything that loses the page's layout (widths, heights, auto-grow, selected
  state).

## Structure

A product area lives across three mirrored layers, by convention:
- `views/<Area>Page.tsx`: the page-level view (thin; keep heavy state in a hook/module).
- `components/<area>/…`: that area's composed components.
- `lib/<area>.ts`: its typed API client + types (the only place that talks to `/api`).

Prefer moving non-trivial view state into a `hooks/` or `lib/` module so it is testable
without rendering the whole page.

## Testing

Colocate `*.test.ts(x)` next to the source. Test **behavior and the contract** (what a
user or caller relies on), not implementation detail. Pure logic (`lib/*`) is the
cheapest, highest-value place to test; render components for the behavior that matters
(e.g. a verdict never renders as "verified" unless it is sound).

## Vendored: do not hand-edit

`components/ui/*` is generated by the shadcn CLI and `components/ai-elements/*` is pulled
from the ai-sdk registry. Both are excluded from Biome and are regenerated, not edited:
compose around them instead. Two exceptions carry over on regeneration: the existing
local customisations (e.g. `ui/button.tsx`'s `chrome` depth), and the `cn` rewrite below.

The shadcn CLI now emits `import { cn } from "cn"` in generated files; rewrite that one
import to `import { cn } from "@/lib/utils"` after every `shadcn add`, because that `cn`
carries the type-scale merge config (`src/lib/utils.ts`) that the raw `cn` package lacks.
